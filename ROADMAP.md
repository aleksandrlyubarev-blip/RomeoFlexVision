# NeutronVision QC — Roadmap: 3-недельный спринт консолидации

> **Статус:** план. Составлен 2026-05-21.
> **Горизонт:** 3-недельный спринт (22 мая – 11 июня) + путь до камера-прототипов (конец июля).
> **Контекст:** репозиторий накопил 9 подпроектов и превратился в «магазин идей». Цель спринта —
> довести ядро до защищаемого, тегнутого состояния и подготовиться к hardware-фазе. Период
> разработки продлён до конца июля: к этому моменту будут первые прототипы камер с ПО для
> тестирования идей **NeutronVision QC**.

---

## 1. Цель спринта

За 3 недели репозиторий перестаёт быть «магазином идей»:

1. **Шум убран** — висящие PR закрыты, непрофильные проекты архивированы, README исправлен, ребрендинг проведён.
2. **Трек A (checker)** доведён до реального, **офлайн-способного**, готового к прототипу состояния.
3. **Трек B (rhaef_v2 + roboqc_data)** — 6-агентный пайплайн **хотя бы раз обработал реальное изображение** end-to-end; синтез данных расширен с 1 дефекта до wedge-набора.
4. Каждый из трёх ядровых проектов — в **тегнутом, документированном** состоянии. Ни одного «наполовину».

Главная проблема сегодня: **ни одна часть репозитория ещё ни разу не обработала реальное фото
собранного узла и не выдала защищаемый вердикт.** `checker` и `rhaef_v2` живут в параллельных
вселенных. Спринт не сливает их (по решению — два трека параллельно), но доводит каждый до
состояния, из которого слияние возможно.

## 4. План на 3 недели

### Сквозные принципы

- **Приоритет — трек A**: именно он едет на прототип. Трек B — второй по приоритету.
- Каждая неделя завершается **зелёным CI и тегом** на затронутых проектах.
- Архивирование = вынести в ветку `archive/<project>` (или отдельный репозиторий), затем удалить из `main`. Код не теряется, `main` чистеет.
- Своя обученная модель за 3 недели **не успевает** (нет реальных данных, `train/` = 0%). Офлайн-движок недели 2 — готовая локальная VLM. Своя модель — фаза после спринта.

## 6. После спринта → камера-прототипы (недели 4–10, до конца июля)

Высокоуровнево, для планирования следующей фазы:

- **Bring-up прототипов:** получить камера-прототипы, развернуть `checker` на целевом железе, отладить оптику/свет.
- **Сбор реального датасета:** фото с прототипов → `roboqc_data` ingest реальных снимков (не только MVTec).
- **Своя модель:** реализовать `train/` и `export_models/` (сейчас 0%) → дообучить на реальных данных → ONNX → офлайн-движок `checker`. **Это естественный шов между треками A и B**: трек B обучает и экспортирует модель, трек A её потребляет.
- **«Бригада»:** заменить эвристические агенты-заглушки `roboqc_data` на реальные LLM-вызовы через `ModelRouter` — для масштабирования синтеза.
- **Решение по слиянию треков:** на основе июльских тестов решить, вызывает ли `checker` 6-агентный пайплайн напрямую.

| Риск | Митигация |
|---|---|
| Спека железа прототипа неизвестна → блокирует выбор офлайн-runtime | Выяснить в первые 2 дня недели 1; по умолчанию портируемый ONNX |
