# Каталог агентов → что можно продавать (подписка / токены)

> **Назначение:** ответ на вопрос «каких агентов из репозитория реально упаковать в подписку или
> токен-биллинг». Companion к `SAAS_STRATEGY.md`. Составлен 2026-06-24.
> **Метод:** код-анализ всех агентных систем репо (rhaef_v2, roboqc_data/brigada, voice-gateway,
> telegram-bot, larmorsight-office, checker) + ROADMAP/AGENTS как рамка. Оценки зрелости — из кода
> (заглушки/`NotImplementedError`/эвристики vs реальные LLM-вызовы), не из маркетинга.

---

## 0. Главный вывод

В репозитории **семь** агент-подобных систем, но только **две реально исполняются end-to-end с
настоящим LLM сегодня**: `checker` (десктоп QC, вердикты через Grok) и `rhaef_v2` RoboQC-пайплайн
(6 узлов через `ModelRouter`). Остальные — либо периферия с заглушками вместо backend-логики
(voice-gateway, brigada, larmorsight-office cloud), либо вообще не агент (telegram-bot).

**Ключевой кросс-факт для биллинга:** учёт стоимости per-call **уже есть** — `ModelRouter.cost_tracker`
+ `litellm.completion_cost()` (`model_router.py:187`). Но он **глобальный module-level singleton без
персистентности и без `tenant_id`**. Значит токен-биллинг для *любого* из агентов упирается в **один
общий недостающий слой: per-tenant метеринг + персистентность**. Это самая высоко-рычажная задача —
она разблокирует токенную монетизацию сразу всего портфеля, а не одного агента.

## 1. Карта: агент → модель монетизации → зрелость → блокер

|---|---|---|---|---|---|
| 1 | **checker** (десктоп QC) | Вердикт PASS/FAIL по фото узла + evidence (JPEG+JSON+PDF) | **Подписка** per-станция / per-seat (десктоп-лицензия) | ✅ Да — реальные Grok-вызовы, тесты, retry/error-handling | Упаковка/лицензирование (DMG/installer); для XPRIZE — Grok→Gemini |
| 2 | **RoboQC** (6-узловой пайплайн) | Инспекция изображения через API | **Токены/usage** (per-инспекция) ± подписка-флор | ✅ Да — реальные LLM-вызовы через router, state-машина, тесты | `tenant_id` + `/inspect` всё ещё заглушка (`StubRoboQCClient`) + auth + персист метеринга |

| 4 | **brigada** (general→major→sergeant→soldier) | Генерация синтетических дефект-данных под класс | **Токены/usage** (per-изображение / per-дефект) | ❌ Нет — агенты **эвристические заглушки** (константы), реален только CV-слой | 4 роли не на LLM (router-backed) + только 1 из 12 дефект-трансформов |
| 5 | **larmorsight-office** (AI-сотрудники) | «Найм» AI-сотрудника (research/devops/sales/finance…) | **Подписка** per-сотрудник/мес (seat) | ⚠️ Локально (Claude Code plugins) работает; **cloud runtime — плейсхолдер** | `server.py` возвращает «placeholder runtime»; нет multi-tenant, метеринга, загрузки скиллов |

| 7 | **telegram-bot** | Лид-воронка / FAQ | — (маркетинг) | ✅ Работает, но **не агент** (pattern-match + статичный FAQ, без LLM) | Исключить из агент-анализа |

## 2. Рейтинг «ближе всего к первому доллару»

1. **checker — продаваемо сейчас как подписка/лицензия.** Единственный продукт с реальным LLM
   end-to-end и тестами. Это **не SaaS** (десктоп, single-user, нет auth — явно «out of scope» в
   README), но per-станция лицензию можно выставить уже. Быстрый путь к выручке под дедлайн 1 авг.
   *Нюанс XPRIZE:* использует Grok, а правила требуют ≥1 Gemini-вызов в проде → добавить Gemini-путь
   (через тот же `ModelRouter`, где Gemini уже first-class).

2. **RoboQC — лучший кандидат на токен-биллинг (SaaS).** Архитектурно готов: реальные вызовы +
   `cost_tracker` уже считает $ per-инспекцию. Каждая инспекция = естественная единица тарификации.
   Блокер — три вещи из стратегии: `tenant_id`, замена `/inspect`-заглушки на реальный вызов,
   per-tenant auth/метеринг. ~3–5 дней.

3. **voice-gateway — естественный per-minute биллинг + уже на Gemini Live (XPRIZE-выгодно).** I/O
   реальный, но 4 инструмента — моки. Без подключения к реальным данным линии (MES/SCADA, которых в
   репо нет) ценность фиктивна. Не продавать, пока tool-executors не реальны.

4. **brigada — «synthetic-data-as-a-service», вторая вертикаль.** Per-изображение биллинг логичен,
   CV-слой — ценное IP. Но 4 агента-заглушки + 1 дефект-трансформ из 12. ~2–3 недели до продаваемости.

5. **larmorsight-office — «AI-сотрудник по подписке».** Привлекательная seat-модель, но cloud-runtime
   = заглушка. До SaaS далеко (загрузка скиллов из GCS, Anthropic SDK, multi-tenant, метеринг). ROADMAP
   уже решил это **архивировать** — переоценивать только если меняем приоритет.

## 3. Рекомендация: что монетизировать и в какой модели

**Двухскоростная стратегия, согласованная с `SAAS_STRATEGY.md`:**

- **Сейчас → выручка (подписка):** продавать **checker** как per-станция лицензию малым сборочным.
  Реально работает, продаётся без облака. Это закрывает «earned revenue от arms-length клиента» под
  XPRIZE раньше, чем дозреет SaaS. *Действие:* добавить Gemini-путь, упаковать установщик, прайс
  $300–900/станция/мес (см. §5 стратегии).

- **2–4 недели → SaaS (токены):** довести **RoboQC** до мульти-тенанта и продавать **per-инспекцию**.
  Это и есть «агентная платформа», заявляемая в XPRIZE. *Действие:* `tenant_id` + реальный `/inspect`
  + **per-tenant метеринг-слой** (см. ниже — он же разблокирует всё остальное).

- **Высоко-рычажная общая задача:** **per-tenant usage-метеринг + персистентность** поверх
  `cost_tracker`. Сегодня он глобальный и эфемерный. Как только появится `tenant_id` в контексте +
  запись расхода в БД (Atlas) → **токен-биллинг включается сразу для RoboQC, voice-gateway и brigada**.
  Это не отдельный продукт — это рубильник монетизации для всего портфеля. Делать сразу после
  RoboQC-tenant-изоляции.

- **Потом (вторая вертикаль):** **brigada** как synthetic-data-as-a-service (per-изображение), после
  замены агентов-заглушек на router-backed.

**Не трогать для монетизации:** `telegram-bot` (не агент), `larmorsight-office` cloud (заглушка,
помечен на архив), `ModelRouter` (инфраструктура, не вертикаль).

## 4. Что проверить/доуточнить

1. **voice-gateway** — есть ли вообще доступ к данным линии у целевого SMB? Если нет MES/SCADA —
   голосовой агент остаётся демо независимо от кода.
2. **checker** биллинг — десктоп-лицензию проще защитить per-станция; нужен механизм лицензий/активации.
3. Цена per-инспекции для RoboQC — посчитать по реальному COGS (Gemini Flash + Cloud Run + Atlas) на
   первой партии, чтобы подписка-флор ≫ COGS (см. §5 стратегии).
