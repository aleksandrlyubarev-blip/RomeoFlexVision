## 1. Выбор трека и проекта

### Трек: **Work and Productivity** (рекомендация)

Обоснование: NeutronVision QC — это инструмент, делающий команды (операторов QC, инженеров
качества) быстрее. Прямое попадание в формулировку трека «tools that make teams faster or more
effective… workflow automation… back-office operations». Developer Tools — запасной вариант
(см. вариант B), Education и Apps for Your Life не наши.

### Вариант A (рекомендация): «Inspection Copilot» — станционный демо-инструмент QC

Однонедельная, автономная, демонстрируемая выжимка идеи NeutronVision Checker:

- **Вход:** фото/кадр собранного узла (upload или webcam) — только синтетические/публичные
  примеры.
- **Шаг 1 — frame quality gate:** blur/exposure-проверка кадра (локально, без модели).
- **Шаг 2 — вердикт GPT-5.6 (vision):** structured output — `verdict / defect_class / confidence /
  evidence_regions / reasoning`.
- **Шаг 3 — human-in-the-loop review:** оператор подтверждает или переопределяет вердикт
  (перенос идеи FrictionGate в минимальный UI).
- **Шаг 4 — evidence record:** каждая инспекция → immutable JSON-запись (append-only log),
  экспорт отчёта.

Это ровно наш публичный питч («вердикт на станции + evidence log + human review»), но в объёме,
который реально собрать за неделю в Codex, и без единого куска коммерческого кода.

### Вариант B (запасной): Developer Tools — «video → labelable dataset» CLI

Обёртка идеи `OVERNIGHT_TASK.md` (сэмплер кадров + provenance CSV + near-duplicate pruning +
quality gate + GPT-5.6 pre-ranking «likely defect») как самостоятельный dev-инструмент для
подготовки vision-датасетов. Плюс: почти всё — детерминированный код, судьям легко тестировать.
Минус: слабее демонстрирует GPT-5.6 и хуже продаёт NeutronVision-нарратив.

**Решение по умолчанию — вариант A.** B выбирать только если к среде (16.07) A не собирается
end-to-end.

## 2. Новый публичный репозиторий — обязательно

Хакатон требует ссылку на код: публичный репо **с open-source лицензией** либо приватный с
доступом для `testing@devpost.com` и `build-week-event@openai.com`.

Строить в **свежем публичном репозитории** (например, `inspection-copilot`), а не здесь, потому что:

1. `ROADMAP.md` §2: текущий репо движется к приватности, а его git-история несёт LarmorSight —
   отдавать её судьям нельзя.
2. Чистая история «создано в Codex за Build Week» — это буквально критерий оценки; репозиторий
   с длинной Claude-историей подрывает нарратив «built with Codex».
3. Судьям нужен маленький репо с README, который запускается за минуты.

Создание репозитория — **только человек** (вне GitHub-scope Claude Code). В новый репо не
переносится ничего из: `larmorsight-office/`, `infra/`, приватных промптов `rhaef_v2`,
каких-либо изображений кроме синтетических.

кастомеров, площадок работодателя — ни в README, ни в видео.
