# AI-First Skills Architecture

## Контекст

Кодовая база RoboQC / Romeo FlexVision уже содержит два канала взаимодействия с людьми
(`telegram-bot`, `voice-gateway`) и проработанную многоагентную оркестрацию для synthetic
data generation — [«Бригаду»](./brigada-architecture.md)
(генерал → майоры → сержанты → солдаты).

Чего не хватает: **общего языка**, на котором все эти агенты и люди описывают «что
они умеют делать». Этот общий язык — **skills**.

## Что такое skill

Скилл — это минимальная версионированная единица работы с явным контрактом:

- **манифест** (имя, версия, владелец, описание, схема входа/выхода, риск, теги);
- **исполнитель**: чистая функция `(input, ctx) => Promise<output>`;
- **контекст выполнения**: `runId`, `caller`, `logger`, `approval`,
  `callSkill` — чтобы скилл мог вызвать другие скиллы и при необходимости запросить решение
  человека (HITL).

Скиллы бывают двух видов:

| Вид              | Кто пишет                | Примеры                                    |
| ---------------- | ------------------------ | ------------------------------------------- |
| `business`       | доменные эксперты      | триаж лида, выбор стратегии дефектов, summary звонка |
| `infrastructure` | инженеры платформы     | отправка в Telegram, чтение `scene-ops.json`, CRM-запись |

Это разделение зеркалит реальный оргструктурный риск: в инфра-скиллах заливаются внешние
эффекты (и значит их надо ревьюить), а бизнес-скиллы остаются чистыми функциями
и могут вайбкодиться экспертами без риска для инфраструктуры.

## Компоненты

```
skills/
  src/
    types.ts        — Skill, SkillManifest, SkillContext, SkillResult, HumanApproval
    registry.ts     — SkillRegistry: локальный Skill Store
    runner.ts       — runSkill(): HITL-gate, измерение времени, логирование, композиция
    skills/
      business/
        triage-lead.skill.ts            — пример бизнес-скилла
      infrastructure/
        send-telegram-message.skill.ts  — пример инфра-скилла (factory над transport)
  examples/
    run-triage.ts   — demo, который прогоняет 4 кейса через triage_lead
```

## Как это связано с «Бригадой»

«Бригада» (см. [`brigada-architecture.md`](./brigada-architecture.md)) описывает **как люди и модели
разных размеров распределяют работу**. Настоящий слой описывает **во что именно работа
распределяется**.

- Генерал и майоры «Бригады» принимают решения, **какой скилл** позвать и с какими входами.
- Сержанты и солдаты **выполняют конкретные скиллы** (CV-код, проверка маски, запись меты).
- Хэндлы voice-gateway и telegram-bot это **внешние вызывающие** слои, которые пользуются тем
  же реестром скиллов.

Таким образом, `@rfv/skills` — это общий ABI между всеми сервисами, а не замена им.

## Human-in-the-loop

Любой скилл может пометить себя `requiresHumanApproval: true`. Раннер в этом случае
требует от вызывающей стороны передать `HumanApproval`-канал. Если канал не передан —
вызов фейлится безопасно, без выполнения сид-эффекта. Это даёт «безопасный по умолчанию»
режим для высокорисковых скиллов.

## Что этот PR **не** делает

- не правит `voice-gateway`, `telegram-bot` или лендинг;
- не вводит сетевых/внешних зависимостей (`@rfv/skills` зависит только от Node и TS);
- не выбирает LLM-провайдера и не определяет протокол «Реестра скиллов» между сервисами;
- не вводит хранилище истории вызовов (пока только логи).

Это осознанные ограничения — чтобы skeleton оставался легковесным и получил форму по следам
первых реальных интеграций, а не «в вакууме».

## Следующие шаги (предложения)

1. **Интеграция в voice-gateway**: перевести `rfv-tools.ts` на вызов скиллов через `runSkill`,
   чтобы Gemini Live tool-call физически выполнялся той же реализацией, что и telegram-триаж.
2. **Интеграция в telegram-bot**: в `commands/` вызывать `business.triage_lead` вместо ручных if/else.
3. **Протокол скиллов для Бригады**: обернуть CV-операции сержантов/солдат в `cv.*` скиллы
   и дать генералу/майорам вызывать их по манифесту.
4. **Персистентный журнал**: дописать хранилище вызовов (хотя бы SQLite/JSONL) для аудита
   и последующей дообучающей выборки.
5. **Ремот Skill Store**: когда появятся внешние потребители (например, второй репо Romeo_PHD) —
   вынести реестр в отдельный service с HTTP/gRPC API.
